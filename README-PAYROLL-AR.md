# تحديث CashBox Cloud — رواتب العمال

هذا التحديث يضيف قسم «رواتب العمال» على الرابط `/payroll` داخل الواجهة الرئيسية.

## الوظائف

- رفع ملف Excel بصيغة XLSX أو XLS (حتى 8MB) مع اختيار ورقة الملف وصف العناوين وربط أعمدة البيانات حتى لو اختلفت أسماء الأعمدة.
- مراجعة أسماء العمال ومبالغ الرواتب في جدول قابل للتعديل قبل الحفظ، والتحقق من الأخطاء والأسماء أو الأرقام المكررة.
- حفظ الرواتب لكل شهر (سنة-شهر) دون استبدال ملف سابق بالخطأ.
- فتح الشهر المحفوظ، تصحيح البيانات ثم الاستبدال بعد تأكيد صريح؛ يحتفظ النظام بنسخة البيانات السابقة في سجل التدقيق `audit_logs`.
- تقرير شهري مفصل وملخص تنفيذي قابل للطباعة في صفحة A4 أفقية أو الحفظ PDF من المتصفح، وتصدير Excel.
- تقرير سنوي يبيّن الأشهر المحفوظة وإجماليات الأشهر وإجمالي صافي رواتب كل عامل في 12 عمودًا، وتصدير Excel.
- الصلاحيات: المدير والرئيس التنفيذي للحفظ والتعديل؛ المحاسب للعرض والتقارير فقط.

## ملاحظات مهمة

1. حفظ الرواتب منفصل تمامًا عن معاملات الصندوق والخزينة ولا يغيّر الأرصدة المالية تلقائيًا.
2. ملف Excel الأصلي ومثال PDF **غير مضمنين في الحزمة**؛ شاشة ربط الأعمدة عامة. ضبط الطباعة ليتطابق حرفيًا مع نموذج PDF يتطلب رؤية ذلك النموذج.
3. قيم «الإضافي»، «البدلات» و«السلف» تُعامل كمبالغ مالية بالريال وليس كساعات أو أعداد؛ ولا يحسب النظام ساعات العمل من البصمة.
4. إذا كان صافي الراتب في Excel مختلفًا عن الصافي المحسوب، يظهر تحذير للتأكد. وعند الحفظ يُحفظ الصافي المكتوب في Excel بعد التأكيد.
5. في التقرير السنوي تتطابق سجلات العامل باستخدام رقم العامل إن وُجد؛ وإن لم يوجد، يُستخدم الاسم كما ورد في الملفات بعد توحيد حالة الأحرف والمسافات. يفضّل توحيد أرقام العمال عبر جميع الأشهر.
6. رفع ملف رواتب **لا يعني دفع الرواتب أو تسجيل مصروف محاسبي**؛ الدفع يسجّل بصورة مستقلة في نظامك المالي.

## تطبيق التحديث

- يجب أخذ نسخة احتياطية من قاعدة بيانات الإنتاج قبل أي تحديث.
- أُضيف نموذجا `payroll_months` و`payroll_rows` إلى `backend/prisma/schema.prisma`، وتقوم خدمة `backend/src/services/ensureSchema.js` بإنشاء الجدولين تلقائيًا عند تشغيل Backend. لا حاجة إلى حذف جداول قديمة أو إعادة تهيئة قاعدة البيانات.
- يواصل `backend` استخدام `prisma generate` عند التثبيت/البناء كما هو في المشروع.
- لا ترفع أو تستبدل ملفات `.env` و`.env.local`؛ الحزمة لا تحتوي عليها.
- عند النشر عبر GitHub/Railway، تأكد أن Backend وFrontend كلاهما تلقيا التحديث، لا ترفع الواجهة فقط.
- ابدأ الاختبار باستخدام قاعدة `cashbox_cloud_test` وأنشئ رواتب شهر تجريبي قبل التطبيق على الإنتاج.

## التحقق المحلي

في Backend:

```
npm test
npm run check
```

في Frontend، بعد تثبيت الحزم المعتادة:

```
npm run build
```

هذه الحزمة لم تُنشر تلقائيًا إلى GitHub أو Railway. ينبغي مراجعة اختبار واجهة الرفع وقاعدة البيانات الفعلية قبل النشر الإنتاجي.
